Part 1: Selfie: The Wrong Way vs. the Right Way

To kick this assignment off, I first took a selfie up close to my face, and then took a few steps away and took the same image by zooming into my face. While I'd like to think I look good in all photos, the second one will feature less distortions. While taking a close-up selfie, the distance each of the facial features are from the camera vary significantly, as our noses might be twice as close to the camera as out ears and jaw, which causes the nose to be disproportionately large and the sides of the face to be compressed. Taking the photo from a distance will bring the different features to around the same distance from the camera, creating an image more similar to when other people look at you.

Part 4: Images of the Russian Empire - Colourizing the Prokudin-Gorskii photo collection

Getting started

Prokudin-Gorskii was a Russian photographer who developed a method for capturing colour images in the 20th century. He did this by photographing the same scene three times, each time with a different colour filter (red, green and blue). The three images are then aligned and combined to create a full-colour image. The Library of Congress in the United States has digitized his collection and made it available online, alllowing us to download the images, and recreate the scenes in colour with modern techniques of image alignment and photo editing.

To start off, I visited the Library of Congress to see how they formed the colour images from Prokudin-Gorskii's images. I was then able to create a script in Python to automate some parts of the process, with intermediate steps that allow the user to interact. I've attached the outputs of the riverside scene along with the functionality of my script. I would consider this as my "brute force" method of getting the images aligned.

The in put of the script is a vertical strip with the three filtered images in the order B, G, R.

The script then converts the image to 8-bit scale and splits the image into the individual Red, Green, and Blue layers. The script takes inputs that are 8-bit jpg images as well as 16-bit tiff images.

To help improve the quality of the alignment process, There are a couple of additional measure I put into place.

Each channel features a different filter's view of the scene, so the channels have different overall brightness and contrast. Before scoring, every channel is normalized to zero mean and unit standard deviation, so the metrics compare structure rather than exposure.

Scores (Euclidean distances) are computed only on the interior of the images, with 10% dropped from each side. The plate borders, dust and scan edges are not part of the scene, and np.roll wraps pixels around the image edge when it shifts. Both of these would otherwise skew the score toward wrong shifts.

To help with alignment, the user is to select anchor points. An anchor point is an image feature that you can safely identify in all three images that can be used for image alignment, such as the corner of a building, or the tip of a tree. Two anchors are the default, but the user can select more or less in the terminal window. I've selected three anchors in this example, two are visible in the screen captures I took.

Using these anchor points as a starting point, the script aims to minimize a the Euclidean distance between the pixel values in the three layers by searching nearby locations. You can set this value in the terminal, I started with a value of 40. Once this equation is minimized, the aligned layers are combined to form the final colour composite. Automating the process

Single-scale search

Now that the brute force method is complete, I moved onto a more automated approach. I did this by using an image pyramid to search for alignment at a lower resolution, and then using that as a starting point for the next higher resolution. This allows for a more efficient search, and can also help to avoid local minima in the optimization process.

To see if this idea will work, I first implemented a simple version of the image pyramid approach, the exhaustive search. For every integer shift (dy, dx) in a window of ±15 pixels, the moving channel is shifted with np.roll, scored against the reference (B) on the interior region, and the best-scoring shift is kept. For the smaller images, such as the 00125 of the church and river, this process should not be too costly. Multi-scale image pyramid

Now that I know that minimizing l2 will eventually give me an aligned image, I can proceed with using the pyramid method to improve the efficiency of the search. To handle large images, the same search function is reused recursively in a coarse-to-fine pyramid. The pyramid is built from my own downsampler, which halves each dimension by averaging every 2×2 block of pixels. Averaging acts as a simple low-pass filter, so shrinking the image doesn't introduce aliasing artifacts that could mislead the search. The algorithm works like this:

  1. If the image is large (shortest side ≥ 300 px), downsample both channels by 2 and solve for the shift at that scale.
  2. Multiply the returned shift by 2 to convert it to the current resolution.
  3. Refine it with a tiny exhaustive search of ±2 pixels around the estimate.
  4. At the coarsest level (shortest side < 300 px), there is no estimate to start from, so do the full±15 px search around (0, 0).

A ±15 px search on a tiny image corresponds to a search range of hundreds of pixels at full resolution. The cost stays low: one 961-candidate search on a small image, then only 25 candidates per level on the way back up. This is what brings full-size plates down to well under the one-minute-per-image target.

I switched to the train image, 00458u, for the rest of the analysis as it is a higher resolution image.

I was curious, so I also went ahead and tested to see how to l2 (Euclidean distance) metric would compare to the NCC (Normalized Cross-Correlation) metric. To make them comparable, the script uses the negative mean square difference between the images, so that both metrics are maximized.
